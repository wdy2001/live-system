# 生活缴费系统 - 产品需求文档

## Overview
- **Summary**: 构建一个面向居民用户的生活缴费管理系统，涵盖电费、水费、燃气费的在线缴费、历史记录查询、计费规则查询及故障报修等核心功能，采用前后端分离架构，后端基于 Python + MySQL，前端基于 React。
- **Purpose**: 为用户提供一站式生活缴费服务入口，简化线下排队缴费流程，支持随时查看缴费历史、计费标准，并提供线上故障报修通道，提升生活服务便利性。
- **Target Users**: 普通居民家庭用户、租户、物业管理方辅助查询

## Goals
- 提供电费、水费、燃气费三种费用的在线缴费功能
- 支持按类别、时间范围、状态等多维度查看缴费记录
- 提供各类费用的阶梯式计费规则展示
- 提供故障报修的提交、进度查询与处理流程
- 实现完整的用户注册、登录、身份认证机制
- 整体系统可在 10 个工作日内完成开发、测试并上线到 GitHub

## Non-Goals (Out of Scope)
- 不接入真实支付网关（使用模拟支付流程）
- 不实现真实的水电燃气公司系统对接（使用模拟数据与计量数据录入）
- 不实现多租户管理与物业管理后台（仅面向终端用户）
- 不实现移动端原生 APP（PC Web 端优先，响应式适配移动端浏览器）
- 不实现发票开具与寄送功能
- 不实现消息推送（短信/邮件/APP推送）功能

## Background & Context
- 技术栈约束：后端必须使用 Python，数据库必须使用 MySQL；前端不限，选择 React + Vite + Ant Design 以提高开发效率与界面一致性。
- 项目周期：10 天完成从 0 到上线的全流程，需要合理拆分每日任务，确保核心 MVP 功能优先交付。
- 部署约束：项目代码需上传至用户 GitHub 仓库，提供可复现的 README 与启动脚本。

## Functional Requirements
- **FR-1 用户注册与登录**: 支持用户名/密码注册、登录、登出，使用 Token（JWT）进行身份认证。
- **FR-2 用户信息管理**: 用户可查看和修改个人基本信息（姓名、手机号、地址等）。
- **FR-3 电费缴费**: 用户可输入户号查询当月应缴电费金额，发起模拟缴费并生成缴费订单。
- **FR-4 水费缴费**: 用户可输入户号查询当月应缴水费金额，发起模拟缴费并生成缴费订单。
- **FR-5 燃气费缴费**: 用户可输入户号查询当月应缴燃气费金额，发起模拟缴费并生成缴费订单。
- **FR-6 缴费记录分类查看**: 支持按缴费类型（电/水/燃气）、时间范围、缴费状态（已缴/未缴/欠费）筛选查看缴费记录，支持明细详情展示。
- **FR-7 计费规则展示**: 展示电费、水费、燃气费的阶梯计费规则、单价、附加费用说明。
- **FR-8 故障报修提交**: 用户可填写故障类型（电/水/燃气）、地址、联系人、紧急程度、问题描述、上传图片后提交报修工单。
- **FR-9 报修进度查询**: 用户可查看自己提交的报修工单列表及工单状态（待受理/处理中/已完成/已取消）。
- **FR-10 模拟计量数据生成**: 系统后台可根据用户户号生成月度模拟用量数据，以便计算应缴金额。

## Non-Functional Requirements
- **NFR-1 性能**: 单页 API 响应时间 < 500ms（P95），支持 100 并发用户无明显性能下降。
- **NFR-2 安全**: 密码必须加密存储（bcrypt），所有受保护 API 需携带有效 JWT Token，SQL 注入防护（ORM），跨站请求防护（CORS 配置）。
- **NFR-3 可维护性**: 代码结构模块化，前后端分层清晰，关键逻辑有注释与单元测试。
- **NFR-4 可用性**: 提供初始化脚本，一键生成数据库表结构与测试数据；README 包含完整启动步骤。
- **NFR-5 兼容性**: 支持主流浏览器（Chrome/Firefox/Safari/Edge 最新两个版本）。

## Constraints
- **Technical**: 后端 = Python 3.9+ + FastAPI + SQLAlchemy + PyMySQL；前端 = React 18 + Vite + Ant Design + Axios；数据库 = MySQL 8.0+。
- **Business**: 10 天交付窗口内必须完成核心功能（FR-1 ~ FR-9）及联调测试。
- **Dependencies**: 需要依赖第三方库（FastAPI、Uvicorn、SQLAlchemy、PyMySQL、passlib[bcrypt]、python-jose[cryptography]、python-multipart、React、Antd、Axios 等），需通过 pip 与 npm 安装。

## Assumptions
- 用户本地或部署环境已安装 Python 3.9+、Node.js 18+、MySQL 8.0+ 与 Git。
- 户号为任意格式字符串，系统通过户号与预生成的计量数据匹配。
- 支付流程为模拟：点击"缴费"后直接将订单状态改为"已缴费"，不对接真实支付渠道。
- 报修工单的状态流转由系统管理员或模拟处理，用户端可查看但不可修改工单状态（除取消）。
- 计费规则数据在初始化时由种子数据写入数据库，后续如需调整通过直接修改数据库或新增后台接口完成。

## Acceptance Criteria

### AC-1: 用户可以注册账号并登录系统
- **Given**: 用户首次访问系统
- **When**: 用户填写用户名、密码、手机号并提交注册；随后使用用户名密码登录
- **Then**: 注册成功返回用户信息与 Token；登录成功可访问受保护页面；尝试访问受保护 API 无 Token 时返回 401
- **Verification**: `programmatic`
- **Notes**: 使用 pytest 覆盖注册/登录接口

### AC-2: 用户可查询电费、水费、燃气费的待缴金额并缴费
- **Given**: 用户已登录且系统内存在对应户号的当月模拟用量数据
- **When**: 用户在缴费页输入户号、选择类型（电/水/燃气），点击"查询"
- **Then**: 显示当月应缴金额（按计费规则计算）；点击"立即缴费"后订单状态变为"已缴费"，余额/记录中可查
- **Verification**: `programmatic`

### AC-3: 缴费记录可按类别、时间范围、状态筛选查看
- **Given**: 用户已登录并存在多条缴费记录（不同类型、时间、状态）
- **When**: 用户在记录页选择筛选条件（类型=电费；时间=近30天；状态=已缴费）
- **Then**: 列表仅展示符合条件的记录，分页正确，点击某条记录可查看明细详情（用量、单价、阶梯费用、附加费、总金额）
- **Verification**: `programmatic` + `human-judgment`

### AC-4: 计费规则页展示阶梯式费率结构
- **Given**: 用户未登录或已登录
- **When**: 用户访问"计费规则"页面
- **Then**: 分区展示电费/水费/燃气费的阶梯用量区间、对应单价、污水处理费/燃气附加费等说明；数据与数据库计费规则表一致
- **Verification**: `programmatic` + `human-judgment`

### AC-5: 用户可提交故障报修单并查询进度
- **Given**: 用户已登录
- **When**: 用户在报修页选择类型（如"电路故障"）、填写地址、联系方式、问题描述并提交
- **Then**: 报修单创建成功且状态为"待受理"；在报修列表中可查看该工单；用户可取消"待受理"状态的工单（变为"已取消"）
- **Verification**: `programmatic`

### AC-6: 密码安全存储与 API 鉴权
- **Given**: 用户注册成功
- **When**: 直接查询数据库用户表
- **Then**: password 字段为 bcrypt 哈希而非明文；非登录、注册、计费规则接口返回 401 当请求头缺少 Bearer Token 或 Token 已过期
- **Verification**: `programmatic`

### AC-7: 系统可一键初始化并运行
- **Given**: 已安装依赖且 MySQL 已启动并配置好连接
- **When**: 执行后端初始化脚本（建表 + 种子数据）与启动脚本，前端启动脚本
- **Then**: 数据库表结构完整、计费规则与测试数据存在；前后端均可访问并通过登录、缴费、报修、查看记录等主流程验证
- **Verification**: `programmatic` + `human-judgment`

### AC-8: 代码已上传至 GitHub 仓库
- **Given**: 所有功能开发、测试完成
- **When**: 检查 GitHub 仓库
- **Then**: 仓库包含 backend/、frontend/ 代码、README.md、.gitignore、数据库初始化脚本；提交历史合理；本地克隆后按 README 可复现运行
- **Verification**: `human-judgment`
